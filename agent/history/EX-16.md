cada comando de `run.ts`. Ningún valor de credencial se imprimió ni se
escribió en este archivo.

## Implementación

```
npx create-next-app@latest . --typescript --eslint --app --src-dir \
  --import-alias "@/*" --no-tailwind --use-npm --disable-git --yes --no-agents-md
```

- `--disable-git`: el directorio ya era un repo git clonado (`.git` propio);
  evita que `create-next-app` intente inicializar uno nuevo encima.
- `--no-tailwind`: no pedido en el plan.
- `--no-agents-md`: scaffold mínimo, sin artefactos fuera de lo pedido.
- Se generó `src/app/` (App Router), ESLint (`eslint.config.mjs`,
  flat config), TypeScript estricto, `.gitignore` estándar de Next.js
  (`.next/`, `node_modules/`, `.env*`, etc. — ya cubre lo necesario, no se
  tocó).

### Alias de import (`tsconfig.json`)

Sustituido el alias genérico por defecto (`@/*` → `./src/*`) por los alias
específicos por categoría de `references/web.md` (singular, uno por carpeta):

```json
"paths": {
  "@component/*": ["./src/components/*"],
  "@hook/*": ["./src/hooks/*"],
  "@store/*": ["./src/stores/*"],
  "@provider/*": ["./src/providers/*"],
  "@i18n/*": ["./src/i18n/*"],
  "@util/*": ["./src/utils/*"],
  "@lib/*": ["./src/lib/*"],
  "@theme/*": ["./src/themes/*"],
  "@type/*": ["./src/types/*"]
}
```

Las carpetas correspondientes (`components/`, `hooks/`, etc.) no se crearon
vacías: no hay todavía código que colocar en ellas (nada que crear
especulativamente, ver skill `architecture`). Se crearán en la primera tarea
que necesite cada una.

## Gate de calidad

### Autorevisión (`security` / `performance` / `accessibility` AA)

- `security`: no aplica de forma sustantiva — scaffold sin inputs de
  usuario, sin auth, sin endpoints propios, sin credenciales en el diff.
  Único punto a vigilar: `.env*` ya está en `.gitignore` por defecto del
  template.
- `performance`: no aplica — sin queries, listados ni llamadas de red
  propias todavía; el único contenido es la home boilerplate del template.
- `accessibility` (AA, `repos[].accessibility.level`): `lang="es"` corregido;
  el resto del markup generado por `create-next-app` (encabezado único,
  `alt` descriptivo en las imágenes del logo, enlaces con `rel="noopener
  noreferrer"` en `target="_blank"`) ya cumple el nivel A/AA por defecto. No
  se tocó el contenido de la home (fuera de alcance del ticket).

### Checks automatizados

```
npx tsc --noEmit        # sin errores
npm run lint             # sin errores/warnings
npm run build             # build de producción exitoso (Turbopack)
```

Todos en verde. No hay tooling de tests configurado (`package.json` sin
script `test`) — coherente con el plan ("no instalar tooling de tests, fuera
de alcance de un scaffold inicial"); no se instaló nada por iniciativa
propia.

### Hallazgo (no bloqueante)

`npm install` deja **3 vulnerabilidades de severidad alta** reportadas por
`npm audit` (transitivas de `next` vía `postcss` y `sharp`). El propio `npm
audit fix --force` propone como única solución degradar `next` a la versión
`9.3.3` — una regresión mayor e inviable, no una corrección real. No se
aplicó ningún cambio de dependencias por esto; queda señalado para que se
revise cuando existan parches reales en `next`/`postcss`/`sharp`, en vez de
forzar un downgrade que rompería el scaffold.
